# AI運用プレイブック（提案・未適用）

対象: 57hustler全体。既存の `CLAUDE.md`、`AGENTS.md`、各プロジェクトの `CLAUDE.md` を置き換えない。矛盾があれば既存のプロジェクト固有ルールと安全ルールを優先し、判断を求める。

## 実行手順（Harness）
1. **調査**: 関連コード・設定・既存 `references.md`・直近の失敗記録・本番公開経路を読む。停止中の事業やワークフローを勝手に再開しない。
2. **計画**: 変更対象・対象外・検証方法・失敗時の戻し方を短く定義。追加費用・外部送信・本番影響を明示する。
3. **実装**: 最小差分で実行。秘密情報をコード・ログ・PRに書かない。機微データは公開リポジトリに置かない。
4. **検証**: 静的検査→単体/統合テスト→必要なら本番実確認。push・build成功だけで完了としない。既存 `CLAUDE.md` のDefinition of Doneを遵守。
5. **反証**: 正常系だけでなく、失敗条件・未対応ケース・意図しない副作用を探す。
6. **記録**: 再現可能な成功手順だけを対象プロジェクトの `references.md` に短く残す。失敗は症状・原因・未解決事項・再試行条件を記録。再利用価値がない手順はSkill化しない。

## コンテキストの使い分け
- 共通の安全・完了条件: 既存 `CLAUDE.md` / `AGENTS.md`
- 事業の固有制約: 各事業の `CLAUDE.md`
- 実証済みの手順: 各事業の `references.md`（存在する場合）
- 未確認の仮説: 「仮説」と明記し、事実や実績と混同しない
- Skills: 成功した反復作業が3回程度確認され、手順が安定した場合のみ候補化。数は増やさず、必要時に読み込む。

## 権限境界
- オーナーは最終判断、AIは調査・準備・検証を担当。
- 本番デプロイ、外部投稿、課金、資金移動、実売買、停止ワークフロー再開は、当該操作についての明確な承認なしに実施しない。
- 読み取り調査と提案は安全側の既定。外部システムの権限が不足する場合は実施済みと偽らない。

この文書は運用提案であり、既存のルールファイル・ワークフロー・本番動作を変更しない。
