# レンズナビ Threads 投稿方針

2026-10-28、オーナーの指示を反映。

## 読者と目的
「安く買いたい」「度数の見方が分からない」「ネット注文が初めて」という人に、眼科で確認したいつもの製品を、実店舗以外にネットで買う選択肢があることを伝える。単なる共感投稿より、購入時の疑問を一つずつ解決する。

## 投稿の柱
1. ネット購入も選択肢：製品と処方内容の確認→購入先の条件確認→注文の順。
2. 度数・規格：箱・指示書のPWR/SPH、BC、DIA、左右、乱視用などの項目。視力の数値から自己処方させない。
3. 安さの比較：同じ製品・枚数・箱数・送料をそろえる。「ネットなら必ず安い」「未確認の最安価格」は使わない。
4. 購入手順：処方箋提出条件、数量、左右、届け先を確認。初めて・変更時の眼科確認と定期検査を省かない。「眼科不要」「誰でも処方なしでよい」と伝えない。

## リンクと実装
- 必要な投稿には内容に合うレンズナビの記事を直接添える。対象は検証済みwww.lens-navi.jp/column/配下のみ。
- リンク付きメッセージは【PR】を明示し、本文・URL・表記を合わせて500文字以内。サイト内の広告表記も維持。
- utm_source=threads、utm_medium=social、utm_campaign=lens_online_buying_202610、utm_content=lens_day_番号を付ける。訪問・比較遷移・購入先クリック・確定報酬を区別する。
- 本文だけの通常投稿と、楽旅・MITAMAの仕様は維持。レンズのトピックは「コンタクト」。
- 原稿を直した場合、previousTextsに以前の本文を残す。全文・旧本文・同一キャンペーンURLで重複判定し、原稿変更を理由に同じ予定分を再投稿しない。
- 日程と頻度はPR #162の承認済み計画を維持。今回の5原稿・リンク対応も本人の明示指示で承認済み。テスト後に反映し、実投稿成功はpostId取得後に判定する。

## 2026-11-11 運用転換：購入先クリックを第一指標にする

オーナー承認により、レンズナビのThreads施策を「投稿本数を維持する」から「読者が同じ製品の購入先を比較し、購入先リンクをクリックできる」へ転換する。編集方針は維持しつつ、評価と優先順位を変える。既存の投稿日時・認証・安全ガードはこの文書変更では変わらない。

### 評価する数字（7日・前7日比較）
1. 本番ホスト `www.lens-navi.jp` のThreads UTMセッション
2. 記事から比較・商品ページへの遷移（`comparison_navigation`、取得できる場合）
3. **`affiliate_click` の実数・リンク先媒体別内訳（第一指標）**
4. ASPの確定報酬（最終指標。未取得なら不明として扱い、クリックから売上を推定しない）

原稿番号・投稿ID・リンク先URL・UTMを紐づけ、閲覧・フォロワー数の増加だけでは成功判定しない。GA4の計測が失敗したら0件と記載せず計測復旧を先に行う。既存の `scripts/fetch-ga4-analytics.ts` と `scripts/report-affiliate-evidence.mjs` を再利用し、新規有料監視を増やさない。

### 収益導線を最優先で改善する順番
1. 購入直前の意図：「同じ製品を1箱だけ」「送料込みで合計いくら」「左右の度数・BC・DIAを間違えずに注文」。事実で確認できない最安・割引率は書かない。
2. 該当する記事・比較ページへの最短のリンク。単なるプロフィール誘導より、内容に対応した検証済みの比較先を優先。リンク付き投稿は【PR】表示とUTMを付ける。
3. 記事→商品比較→実際の購入先リンクをスマホで通して点検。既存A8の検証済み導線を維持し、未検証の楽天CTAは有効化しない。
4. 流入が増えても購入先クリックが増えない場合は投稿増量より導線改善を優先。クリックが増えてもASP確定報酬が出ない場合は広告主条件・媒体の収益性を点検。

### 投稿の運用原則
- 予定の有無だけで成功扱いせず、Actionsの実行結果・公開postIdと公開画面を照合する。
- 11/18以降の予定を期限前に確認し、原稿枯渇を放置しない。自動再送が曖昧な場合は必ず履歴照合を先にする。
- 無差別フォロー・同内容の連投をしない。読者の疑問を解決して比較先を案内する。
- 誤った医療案内、自己処方の促進、値引き保証をしない。既存ブランドの認証・投稿は変更しない。
- 数字・実装・確認状況の追跡は既存Issue #100に一本化する。
