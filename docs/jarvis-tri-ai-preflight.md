# JARVIS 3AI協議 — 最終接続前の実装（2026-11-18）

## 追加したもの
- 既存の認証済み JARVIS チャットに「3AI協議の準備」を追加
- POST /api/jarvis/triage は同一Origin、認証、JSON、500文字制限を確認
- GPT（経営判断）、Claude（実装査読）、Gemini（独立反証）の同一相談パケットを生成
- 作業権限を read_only / draft_only / owner_approval に保守的に分類
- 3名の実回答が揃うまで合意扱いしない純粋関数 reconcileReviews
- 課金API、プロバイダーへの送信、Issue起票、マージ、本番公開、SNS投稿は **実施しない**

## 現状の限界
この機能は「3AIの実協議」ではなく **協議の受付準備・依頼票生成**。
受付IDは画面表示のみで、保存されない。各AIの本人チャット履歴は自動共有されない。
3モデルの実回答取得、相互査読のループ、永続監査台帳、費用メーター、
プロバイダー共通認証、チャット横断での受付は未実装。既存CEO実行の稼働とは別機能。

## 最終接続に向けて必要なゲート
1. 各サービスの正式なAPIまたは許可された連携経路を確認（ChatGPT/Claude/Geminiの有料チャット契約はAPI呼出枠とは別の場合がある）
2. 3AIの実行時予算上限、回数上限、通信先、秘密鍵のVercel側サーバー環境変数設定をオーナーが承認
3. サーバー側の実行キュー、冪等キー、失敗・タイムアウト・部分合意の扱い、監査保存、プロンプト注入対策を追加
4. 個人情報や商用機密を外部APIに送る前のデータ分類を追加
5. 3名の実回答と根拠を保存して reconcileReviews に渡し、異論は再検証。合意と業務実行の承認は別
6. 開発環境で型チェック・ビルド・認証試験・意図しないAPI課金ゼロの確認
7. PRレビュー後に既存の承認済み公開手順へ引き渡す

## 受け入れ試験
- 未ログイン POST -> 401、別Origin -> 403、非JSON -> 415、空/501文字 -> 400
- 一般質問 -> read_only、実装依頼 -> draft_only、本番公開等 -> owner_approval
- 3名が揃わない -> incomplete、1名が反対 -> needs_review、3名賛成 -> agreement。ただし自動公開不可
- どのケースでも課金APIを呼ばず、実行済み・回答済みを主張しない

## 既存仕組みとの分離
- jarvis-affiliate/、Claude専任Issueとブランチ、既存CEOの毎時運用には一切変更しない
- 既存の収益集計やダッシュボードの本番挙動は変更しない
