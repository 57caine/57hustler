# 株式戦略AI研究・検証プロトコル（研究用・未稼働）

目的: 雰囲気やAIの断定ではなく、取得元を明記したデータで投資仮説を作り、反証と再現可能なバックテストを行う。利益保証や売買推奨の自動化ではない。ユーザーの実取引・証券口座・認証情報には接続しない。

## 研究対象と前提
- 初期候補: 日本株（半導体・水関連を含む）。候補選定は調査の出発点であり、優位性の証明ではない。
- 初期段階は現物株・レバレッジなし・実資金なし。空売りや信用取引データは、まず市場環境を説明する補助変数として扱う。
- 研究用データと実際の口座資産を分離する。実資産や個人情報を公開GitHubに保存しない。
- 追加課金が必要なデータ/APIは事前承認があるまで導入しない。

## 1. データ収集・品質管理
- 株価（OHLCV）、出来高、株式分割・配当・上場廃止を考慮した履歴、売買単位、売買手数料、取引カレンダーを確認。
- 信用買残・売残などの信用取引データは、公表頻度・公表時刻・対象範囲を記録。未来の公開値を過去の判断時点で使わない。
- データソースURL、取得日、更新頻度、ライセンス、欠損・補正履歴を記録。無料データで検証できないものは「検証不可」とする。

## 2. 戦略仮説
- AI役割A: 事実と先行研究を整理し、シンプルで反証可能な候補を複数作る。
- AI役割B: 先読みバイアス、銘柄選別バイアス、データ漏洩、過剰最適化、制度変更を批判的に検査。
- AI役割C: データとコードを独立検証し、再現性・実行可能性を確認。
- 全戦略に「対象銘柄・エントリー・イグジット・ポジション上限・損切り条件・停止条件・比較対象」を明記。

## 3. バックテスト
- 時系列順の訓練期間・検証期間・完全未使用期間を分ける。未使用期間はパラメータ調整に使わない。
- 実行時点で入手できた情報のみを使用。売買タイミングと約定価格の仮定を明記。
- 売買手数料、スプレッド、スリッページ、税金の扱い、流動性、単元株制約を反映。
- 利益額だけでなく、最大ドローダウン、勝率、損益比、取引回数、保有期間、年率換算成績、単純保有・TOPIX等の比較を報告。
- 上昇・下落・横ばい局面、期間ずらし、コスト悪化、銘柄入替えなどの感度分析を行う。
- 期待通りでない結果や失敗戦略も保存。過去成績は将来を保証しない。

## 4. 採用判定と安全境界
- 合格条件は事前定義。未使用期間でも安定し、費用控除後で比較対象を上回る根拠があること。
- 不合格・データ不足・検証未完了はそのまま報告し、都合の良い結果だけを採用しない。
- 次段階はペーパートレードで一定期間の前向き検証。実取引・自動発注は別途明示承認とリスク審査が必要。
- 「月5万円」等の収益目標から逆算して高リスク戦略を正当化しない。元本割れの可能性を前提とする。

## 5. AIの学習記録
- 1件ごとに、仮説、使用データ、当時利用可能な情報、テスト条件、結果、失敗理由、次回改善点を記録。
- 「AIができなかったこと」を記録し、新しいツールが使えるようになった際に再評価する。
- 人間の判断が必要な事項（許容損失、投資期間、資金投入）は、研究結果と分離して提示。

## 現在のステータス
研究プロトコルのみ作成。市場データ取得、バックテスト、証券口座連携、売買注文、外部サービス課金は未実施。
