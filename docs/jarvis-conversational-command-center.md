# JARVIS Conversational Command Center — 要件とMVP設計

更新：2026-11-17 / 状態：設計のみ（未実装・未デプロイ）

## 0. オーナー意図（最重要）
本来の「JARVIS」はLP自動量産器ではなく、GPTのような自然言語会話によって本人の事業横断タスクを理解し、状況を集め、ChatGPT/Claude/既存GitHub Actions等に安全に仕事を渡し、根拠と結果を会話で返す個人用AI司令塔。
既存 `jarvis-affiliate/` は一つの実行機能・収益実験対象として保持し、削除・命名変更・本番設定変更・Claude専任ブランチ変更はしない。

## 1. 達成条件（チャットで言えること）
- 「今日どう？」→ 各事業の本番状態、計測値、確定報酬、未取得、優先課題を**データ出典と期間付き**で端的に返す。情報を取得できない場合0と言わない
- 「GO」→ 直前に示した具体的タスクを既存権限・承認範囲の中で実行、実行結果（コミット、PR、テスト、公開確認）を返す。「GO」だけで新規課金・決済・本番公開許可を推定しない
- 「Claudeと分担して」→ GitHubの既存 `claude-task` handoff（Issues→Claude予約→Draft PR）を利用し、受理/実行/完了をログで確認。依頼を保存しただけでClaudeが実行したとは言わない
- 「何が売れた？」→ SNS閲覧→サイト流入→クリック→ASP発生→確定→利益まで区別して報告。各サービスに対するアクセス権が無ければ欠測として記録
- 音声は将来機能。まずテキスト会話。音声操作や常時待機を実装済みとしない

## 2. 実装経路の比較・推奨
- **Phase 0（即時・追加課金0）**：既存ChatGPT会話をフロントエンドとし、接続済みGitHub等、既存CEO自走運用と `docs/ceo-agent-graph.md`、既存Claude handoffを利用。新規のチャット画面やモデルAPI契約は作らない。利用可能なツール/権限の範囲でのみ実行。ChatGPT会話そのものを外部アプリから勝手にAPIとして呼べるとは想定しない
- **Phase 1（MVP候補、実装は別途判断）**：CEOダッシュボードに専用チャットUI。サーバー側認証、メッセージ処理、ツールレジストリ、監査ログ、権限ゲート。LLMバックエンドを選定（OpenAI API等はChatGPTサブスクと別課金になりうる）。追加課金0の方針により、モデル接続手段・料金・権限の合格確認まで実装を止める
- ChatGPT内で会話しながら各既存コネクターを使う形が、現段階では最も軽く確実。外部UIの独立JARVISはコストと接続条件を確認後

## 3. MVPの部品と安全境界
1. Conversation Interface: 要約、直前会話のタスク参照、具体的GO対象の同定
2. Intent→Task Planner: 目的、範囲、担当、証拠、完了条件、差し戻し、承認種別を構造化
3. Read-only Tool Adapters: GitHub main/PR/Actions、Vercel、GA4/GSC、ASPの**接続済みで認可された**範囲。取得不能は unknown
4. Executor: 既存CEOの単一自走タスクとClaude専任hand-offに委譲。新規cronを増やさない。待機中タスクと重複作成しない
5. Approval Gates: 認証・決済・外部公開・規約/リンク変更・大きな本番挙動・新規課金はオーナー判断。口頭の曖昧なGOだけでは不可
6. Evidence Ledger: タスクごとに状態 / コミットSHA / PR / Actions実行ID / 検証日時 / 実測値 / 失敗理由を記録。監視の成功と改善成功と売上を区別
7. Results: 事業別確定報酬、利益、計測可能な中間指標、次の1手を自然な文章で出力

## 4. MVP受け入れ試験（未実行）
A. 「昨日から何が変わった？」→ 同一指標・同一期間で比較し、期間や出典がない数値は不明
B. 「レンズナビの改善をGO」→ 既存PR/Issueを見て重複回避、担当外を触らず、成果物と状態を報告
C. 「Claudeへ」→ 既存専任キューへ渡し、受領前は「依頼済み」以上と表現しない
D. 「売上3万円達成？」→ ASPの確定報酬のみ集計。noteやクリック数を混ぜない
E. 「全部公開して」→ 対象、権限、ロールバック、明示承認と必要な認証確認なしに危険な一括処理をしない
F. ツール失敗→空欄や0で埋めず、理由を示し再開条件を残す

## 5. 事業戦略との関係
最優先は売上検証（CEO #207）。JARVISの開発自体を売上が立ったこととして数えない。作業効率向上は別のKPI（本人操作回数、GO後の完了率、根拠のある実行率、AIの重複処理率）で測る。
- アダルトアフィリエイトはClaude担当を維持。既存の専任ブランチ/アカウント/コンテンツは権限なく触れない
- レンズナビの収益実測と継続、楽旅の既存投稿を止めない
- 旧JARVIS-Affiliateは独立して安全ゲート・掲載許可を維持し、LP量産を急がない

## 6. 次の実務
1. ChatGPTを司令塔とするPhase 0で「今日どう」「GO」「本人タスク」を同一フォーマットで運用し、実ログから完了率を測る
2. CEOダッシュボードの既存UI/アクセス状態を点検し、会話画面追加の実装要否と費用を見積もる
3. 独立チャットに必要なモデル接続方法が追加費用なしで実現可能か確かめる。無理ならPhase 0を継続し、勝手に課金しない

**この文書は実装方針であり、会話AI・Claude完全連携・音声・常時自走が実現済みであることを意味しない。**
