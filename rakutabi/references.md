# 楽旅くん：うまくいった施策・型の記録

実際に試して効果や安全性を確かめられたものだけを残す。うまくいかなかったものは、理由と一緒に「避けること」に書く。

## 仕組み・運用

- **楽天APIはGitHub Actionsからだけ呼ぶ**（2026-09-26〜）
  - 開発環境・閲覧者のブラウザからは呼ばない。Refererは登録済みの lens-navi.jp を送る（Node標準のfetchはRefererを送らないため `node:https` を使う）
  - 楽天ウェブサービスの「許可されたWebサイト」に vercel.app を追加せずに済んだ
- **本番公開はActionsのmainからだけ**（2026-09-29、PR #15）
  - 起動条件・ジョブ条件・公開スクリプトの3か所でmain以外を止める。1か所の閉め忘れでも本番に出ない
  - 作業ブランチへのpush・作業ブランチ指定の手動実行では公開されないことを実際に確認済み
- **Vercelのビルド枠を使わない公開**（`vercel build` → `vercel deploy --prebuilt --prod --archive=tgz`）
  - 約750ページ・20,000ファイルでも上限に掛からず、他事業のデプロイ待ちも起こさない
- **公開後の全ページ機械チェック**（`scripts/verify-production.sh`）
  - HTTP 200・noindex・送客リンクの属性・写真クレジット・解説文の有無を全ページで確認する。代表1ページだけの確認で見落としていた問題（写真クレジット漏れ）をこれで見つけた

## コンテンツ

- **絞り込み条件は取得データの記載から判定し、「目安」と明記する**
  - 施設情報APIの「館内設備」「食事場所」「お風呂について」「バリアフリー」「駐車場」から判定すると、紹介文だけより該当件数が増える。例：温泉宿386件で、部屋食・個室食121件、送迎186件
  - 駐車場は「1泊800円」のように料金の記載があるものを除外し、誤って「無料」と判定しないようにした
- **テーマページに「宿を選ぶときのポイント」を置き、各ポイントに対応する絞り込み名を添える**（2026-09-29、子連れ・親孝行）
  - 解説と絞り込みが一対一で対応していると、読んだあとにすぐ宿を絞り込める
- **写真はUnsplashの説明文（alt_description）で選ぶ**
  - 補足説明（description）は地名が入るため誤判定しやすい。温泉写真はalt_descriptionで「hot spring」等を優先して選び直して改善した

## 避けること

- 作業ブランチを作り直すための履歴の書き換え（force push）。変更点の判定がずれて、意図しない公開処理が起動した（2026-09-28）
- 連続したpush。公開処理が終わるのを待ってから次のpushをする
