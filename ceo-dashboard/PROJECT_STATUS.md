## 今回の変更

### データモデル（新規）
- `data/projects-registry.json`: 稼働中6件（レンズナビ／楽旅くん／ペット避難／夜中のおじさん／
  出口のノート／雑草おじさん）＋停止中4件（資格サイト／保育士比較サイト／東京ラーメンマップ／Etsy）
  の静的情報（目的・現状・ファネル定義・担当AI・紐づくGitHub Actionsワークフロー名）
- `data/ai-team.json`: ChatGPT／Claude／Geminiそれぞれの現在の仕事・次の仕事・完了した仕事・
  判断待ち・ステータス（オーナー手動更新前提）

### 新規ページ（ceo-dashboard/app/配下）
- `/today`: 起動画面。今日やることTOP3（ALERT検知の重複度による代理指標）、判断待ち／AI作業待ち／
  停滞／未更新の件数、緊急ALERT、現在の収益状況（lens-naviのみ実データ）を1画面に集約
- `/projects`: 稼働中6件＋停止中4件（折りたたみ）のカード一覧。プロジェクト名・ステータス・優先度
  （ALERT代理指標）・収益・流入・CV・次のアクション・担当AI・最終更新を表示
- `/projects/[slug]`: プロジェクト詳細。目的→現在の状態→KPI→ファネル→問題→仮説→PDCA→
  次のアクション→担当AI、の9ステップで表示
- `/money`: 収益ダッシュボード。今月/前月収益・プロジェクト別収益・クリック/CV/CVR・目標との差。
  レンズナビのクリック数のみ実データ（affiliate_clickイベント）、それ以外は「収集前」「未取得」
  「準備中」を明示（ダミー値は一切使用していない）
- `/ai-team`: ChatGPT/Claude/Geminiのカード。各フィールドをインライン編集し
  `/api/ai-team/update`経由でGitHub Contents APIに保存する
- `/pdca`: 旧「改善レビュー」を拡張。仮説（既存causes）→実行（新規execution）→結果（新規result、
  自動生成しない）→改善案（既存suggestions）→次のアクション（新規nextAction）の5段で表示・編集

### 既存ページの統合・リダイレクト
- `/column-review` → `/pdca`にリダイレクト（機能は`/pdca`に完全移植、欠損なし）
- `/tasks` → `/alert`にリダイレクト
- `/report-log` → `/alert`にリダイレクト
- `/analytics` → `/money`にリダイレクト（ページ別テーブルは`/money`内に移植）
- ルート`/` → `/today`にリダイレクト
- 上記どのページも実体の`page.tsx`は`redirect()`のみに置き換え、**呼び出し先のAPIルート
  （`/api/column-review/*`・`/api/reports/*`・`/api/tasks`）は一切削除していない**

### ALERT・TODAYの連動
- `ceo-dashboard/lib/alerts.ts`に検知ロジックを集約し、TODAY・PROJECTS・ALERTの3画面が
  同じ関数`buildAlertItems()`を呼ぶことで「ALERTはTODAYと連動させる」を構造的に担保
- 検知する6条件: ユーザー判断待ち／長期間停滞／未更新／KPI悪化／次のアクション未設定／AI作業待ち
- `ceo-dashboard/app/api/projects-activity/route.ts`（新規）: 各プロジェクトに紐づく
  GitHub Actionsワークフローの最終実行日時・結果を取得し、未更新・KPI悪化（実行失敗）の判定に使う

### 優先度スコアの暫定ロジック
- `ceo-dashboard/lib/priority.ts`に分離。フェーズ2は`rankByPhase2Proxy()`がALERT該当カテゴリの
  重み付け合算でTOP3を決める。フェーズ3で優先度スコアエンジンが完成したら、この関数の中身だけを
  差し替えれば呼び出し側（TODAYページ）には手を入れずに済む設計にしてある

### PDCAの自動記録
- AI自動修正PRがダッシュボードの「承認してマージ」ボタン経由で承認された場合、
  `execution`フィールドに承認日時・PR番号・変更内容（PRタイトル）を自動記録する
  （`api/column-review/approve-fix/route.ts`を修正）
- GitHub上で直接PRがマージされた場合（ダッシュボード経由でない場合）も同様に記録する
  （`.github/workflows/auto-fix-pr-merged.yml`を修正）
- `result`（結果）フィールドは意図的に自動生成していない。空欄のままでよく、空欄はPDCA/ALERTの
  「次のアクション未設定」判定に自然に反映される

### 副次的な修正（このタスクと並行して依頼されていたもの）
- `scripts/fetch-ga4-analytics.ts`のGA4集計バグを修正。`totalSessions`が
  「上位20ページの合計」（過少カウント）になっていたのを、ディメンションなしの単純合計クエリに
  変更し、サイト全体の正しい合計を取得するようにした
