# /check-compliance — コンプライアンス監査

対象：$ARGUMENTS（空なら `content/campaigns/` の全LP）

機械チェックと、人の目に近い読み込みチェックの2段階で行う。**「問題なし」で終わらせず、疑って探した上で「見つからなかった」と書く。**

## 1. 機械チェック

```bash
npm run validate -- --json     # 結果は output/validate-result.json
npm run build                  # postbuild でHTMLチェック（PR表記・sponsored・計測属性・Product禁止）
JARVIS_ENV=production npm run validate   # 本番基準での不足（ダミー・未設定）を洗い出す
```

ネットワークが使える場合のみ：`npm run validate:online`（リンク切れ・提携切れの検出）

## 2. 読み込みチェック（各LPのMDと dist のHTMLを読む）

`config/compliance-rules.md` の1〜5章を1項目ずつ確認する。特に以下はNGワード辞書では拾えないので必ず目で見る。

- [ ] **優良誤認**：言い換えた断定（「間違いない」「誰でも」「失敗しない」）、比較対象のない「安い」「早い」
- [ ] **有利誤認**：期限のない「今だけ」、条件を省いた「無料」（無料体験の条件・自動更新の有無）
- [ ] **数値の裏付け**：比較表・本文の数値が `affiliates.json` の `specs` と一致し、`verifiedAt` が30日以内か
- [ ] **創作の疑い**：体験談・口コミ・「〇〇さん（30代）」等の架空人物、出典のない統計
- [ ] **薬機法**：`regulatedCategory` が正しいか（化粧品・サプリ・医療機器なのに `none` になっていないか）
- [ ] **ステマ規制**：PR表記がファーストビュー内にあるか。SNS投稿案（`output/social/`）に `#PR` があるか
- [ ] **ASP規約**：各案件の `notes` に書かれた禁止事項（SNS掲載不可・指名KW禁止等）に違反していないか
- [ ] **リンク**：ショップトップ等、報酬が発生しない遷移になっていないか。`href="#"` がないか
- [ ] **計測**：全アフィリエイトリンクに `data-affiliate-id` と `rel="sponsored"` があるか

## 3. 直す

- 機械的に直せるもの（NGワードの言い換え・属性漏れ）は直して再検証する
- 表現の判断が要るもの（訴求の強さ、ランキング根拠）は直さず、修正案を添えて報告する
- 新しく見つけたNGパターンは `config/compliance-rules.md` の `ng-words` に追加を提案する

## 4. 報告形式

| LP | 重大度 | 項目 | 箇所（ファイル:行） | 内容 | 対応（修正済み／要判断） |
|---|---|---|---|---|---|

最後に「確認したが見つからなかった項目」を列挙する。
